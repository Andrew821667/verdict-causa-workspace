# Стенд на Mac mini: установка и запуск

Комплект ставит «Резонанс» на Mac mini как службу macOS и выпускает его на
поддомен через Caddy с автоматическим TLS.

## Чего этот стенд не делает — прочитайте до установки

**Аутентификации в приложении нет.** Ни входа, ни паролей, ни сессий: изоляция
пространств — инвариант модели, а не защита от постороннего. Кто открыл адрес,
тот видит все дела и может загружать документы. Поэтому в `Caddyfile` включена
базовая аутентификация: без неё выпускать стенд в интернет нельзя.

**Состояние живёт в памяти процесса.** Дела собираются при старте, а
загруженные документы, замечания и пересчёты теряются при перезапуске службы.
Это стенд для проверки разбора, а не система ведения дел; хранилища у него нет,
и притворяться, что есть, он не будет.

**Материалы реальных клиентов сюда загружать нельзя.** Файл не шифруется, не
хранится и не удаляется по расписанию — он живёт в памяти до перезапуска. Для
проверки берите обезличенные документы.

**Формальный результат не является судебным выводом или юридической
консультацией.**

## Что нужно на Mac mini

- macOS с Homebrew;
- Python 3.11 или новее;
- Node.js 20 или новее (нужен только для сборки интерфейса);
- Caddy (`brew install caddy`) — он же получит сертификат;
- доменное имя, A-запись которого указывает на внешний адрес Mac mini, и
  проброшенные на него порты 80 и 443.

## Установка

```bash
git clone <адрес репозитория> ~/verdict-causa
cd ~/verdict-causa
./deploy/install.sh
```

Скрипт создаёт виртуальное окружение, ставит пакет, собирает интерфейс,
проверяет, что стенд поднимается, и печатает следующий шаг. Ничего в системе он
не включает: службу и веб-сервер вы запускаете сами — установка, которая молча
открывает порт наружу, недопустима.

## Служба macOS

```bash
cp deploy/com.verdictcausa.stand.plist ~/Library/LaunchAgents/
# в файле замените /Users/ВАШ_ПОЛЬЗОВАТЕЛЬ на реальный домашний каталог
launchctl load ~/Library/LaunchAgents/com.verdictcausa.stand.plist
launchctl start com.verdictcausa.stand
```

Служба слушает `127.0.0.1:8765` — только локально. Наружу её выпускает Caddy.

Проверка: `curl -s http://127.0.0.1:8765/api/desktop | head -c 200`

Логи: `~/Library/Logs/verdict-causa-stand.log` и `…-error.log`.

Остановить: `launchctl stop com.verdictcausa.stand`,
выгрузить: `launchctl unload ~/Library/LaunchAgents/com.verdictcausa.stand.plist`.

## Поддомен и TLS

1. Откройте `deploy/Caddyfile`, замените `stand.example.com` на свой поддомен и
   почту для Let's Encrypt.
2. Создайте пароль:

   ```bash
   caddy hash-password --plaintext 'ваш-пароль'
   ```

   Вставьте полученный хэш в `basic_auth` вместо заглушки.
3. Запустите:

   ```bash
   sudo caddy run --config deploy/Caddyfile
   ```

   Либо как службу: `sudo brew services start caddy` с этим файлом в
   `/opt/homebrew/etc/Caddyfile`.

Caddy сам получит и продлит сертификат. Порт 80 нужен для проверки владения
доменом.

## Обновление

```bash
cd ~/verdict-causa && git pull
./deploy/install.sh
launchctl stop com.verdictcausa.stand && launchctl start com.verdictcausa.stand
```

Пересборка интерфейса обязательна: данные разбора вкладываются в сборку, и
старая сборка покажет старые выводы.

## Если что-то не открывается

| Симптом | Причина |
|---|---|
| `curl` на 8765 не отвечает | служба не запущена — смотрите `…-error.log` |
| браузер просит пароль и не пускает | хэш в `basic_auth` не соответствует паролю |
| Caddy не получает сертификат | порт 80 не проброшен либо A-запись не обновилась |
| интерфейс открылся, но кнопка загрузки выключена | стенд отдаёт снимок: не собран `web/out` |
