# Задание агенту на Mac mini: поднять стенд «Резонанс» на поддомене

Ты работаешь на Mac mini. Нужно развернуть стенд юридического разбора и выпустить
его на поддомен по HTTPS. Почти всё делает один скрипт; твоя задача — подготовить
машину, проверить сеть **до** запуска и внятно отчитаться.

## Ресурсы: только подписка, никаких API-ключей

**Работай на ресурсах своей подписки.** Не обращайся к платным API языковых
моделей — ни под каким видом.

Конкретно запрещено:

- использовать любые ключи API LLM: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`,
  `DEEPSEEK_API_KEY`, `GEMINI_API_KEY` и любые другие — свои, системные, из
  переменных окружения, из `.env`, из связки ключей;
- брать ключи, токены и настройки **из этого проекта или любого другого проекта
  на машине** и использовать их для своей работы;
- запускать что-либо, что обращается к платному API от твоего имени.

Если задача кажется невыполнимой без платного API — **остановись и напиши
человеку**. Счёт за API при наличии оплаченной подписки — это ошибка, а не
результат работы. Такое уже случалось и стоило денег.

Пароль можешь сгенерировать сам:


Сгенерированный пароль **сообщи человеку в отчёте** — иначе войти будет некому.
Больше нигде его не сохраняй: ни в файл, ни в git, ни в заметки.

## Что это за стенд — прочитай, это влияет на твои действия

- **Аутентификации в приложении нет.** Наружу его закрывает только пароль в
  Caddy. Без него открытый адрес означает, что стенд видит кто угодно.
- **Состояние живёт в памяти процесса.** Загруженные документы и замечания
  теряются при перезапуске службы. Это стенд для проверки разбора, не система
  ведения дел.
- **Материалы реальных клиентов сюда загружать нельзя.** Сам ничего не загружай.
- Формальный результат не является судебным выводом или юридической
  консультацией.

## Сломает ли это другие проекты на машине

Коротко: не должно, и скрипт теперь сам это проверяет — но проверь и ты.

| Ресурс | Риск | Как закрыт |
|---|---|---|
| порт `8765` | занят другим проектом | скрипт проверяет и **останавливается**, если занят |
| порты `80` и `443` | на машине уже nginx или Docker | скрипт проверяет владельца и **останавливается**, если это не Caddy |
| конфигурация Caddy | затереть чужие сайты | чужой `Caddyfile` **не перезаписывается**: делается резервная копия и добавляется одна строка `import` |
| перезапуск Caddy | уронить чужие сайты | перед перезапуском выполняется `caddy validate`; не прошла — перезапуска нет |
| Homebrew | обновление ломает другой проект | **ничего не обновляй**, см. шаг 1 |
| `~/verdict-causa` | затереть чужой каталог | имя новое; если каталог есть — это наш прошлый запуск |
| служба `com.verdictcausa.stand` | конфликт имён | метка уникальна |

**Перед установкой посмотри своими глазами, что на машине уже работает:**

```bash
lsof -nP -iTCP:80   -sTCP:LISTEN
lsof -nP -iTCP:443  -sTCP:LISTEN
lsof -nP -iTCP:8765 -sTCP:LISTEN
brew services list
ls -la "$(brew --prefix)/etc/Caddyfile" 2>/dev/null
docker ps 2>/dev/null
```

Если порт 80 или 443 занят **не Caddy** — остановись и напиши человеку, какой
это процесс. Не выключай его сам: там может быть боевой сервис.

Если `Caddyfile` уже есть — это нормально, стенд подключится к нему вставкой, а
рядом останется копия `Caddyfile.before-verdict-causa.<дата>`.

## Шаг 1. Зависимости

Сначала посмотри, что уже стоит:

```bash
brew --version           # Homebrew должен быть установлен
node --version           # нужен v20 или выше
python3 --version        # нужен 3.11 или выше
caddy version            # если команда не найдена — поставим ниже
```

Ставить можно только то, чего нет:

```bash
brew install caddy       # если caddy version не сработал
brew install node        # только если node вообще не установлен
```

**Ничего не обновляй командой `brew upgrade`.** На машине есть другие проекты, и
обновление Node или Python может их сломать. Если Node старше 20 или Python
старше 3.11 — **остановись и напиши человеку**, какие версии стоят. Обновление
общесистемных пакетов — его решение, не твоё.

---

## Шаг 2. Проверь сеть ДО установки

Это главное, что стоит сделать заранее: скрипт дойдёт до выпуска наружу и там
упрётся, если DNS или порты не готовы.

```bash
DOMAIN="ваш.поддомен"          # подставь

echo "внешний адрес машины: $(curl -s https://api.ipify.org)"
echo "куда смотрит домен:   $(dig +short "$DOMAIN")"
```

**Два адреса должны совпасть.** Если нет — DNS не настроен или ещё не
разошёлся; напиши об этом человеку и не продолжай дальше шага 3.

Порты 80 и 443 должны быть проброшены на эту машину в роутере. Проверить
изнутри нельзя — просто предупреди человека, если сомневаешься. Порт 80 нужен
обязательно: без него Let's Encrypt не подтвердит владение доменом.

## Шаг 4. Запусти установку

Скрипт спросит подтверждение, потом три значения. Их можно передать заранее —
так надёжнее, чем вводить в диалоге:

```bash
cd ~/verdict-causa

export CAUSA_DOMAIN="ваш.поддомен"
export CAUSA_EMAIL="почта@пример.ру"
export CAUSA_OPERATOR="operator"
export CAUSA_PASSWORD="сгенерированный-пароль"

./deploy/bootstrap.sh --yes
```

После запуска сразу очисти пароль из окружения:

```bash
unset CAUSA_PASSWORD
```

### Что скрипт делает и сколько это занимает

| Шаг | Что происходит | Время |
|---|---|---|
| 1/4 | виртуальное окружение, установка пакета, сборка интерфейса на Next.js | 3–10 минут |
| 2/4 | подстановка поддомена, почты и хэша пароля в конфигурацию | секунды |
| 3/4 | служба macOS, ожидание ответа на `127.0.0.1:8765` | до 2 минут |
| 4/4 | Caddy, получение сертификата Let's Encrypt | до 3 минут |

**Скрипт запросит пароль администратора** в начале: Caddy занимает порты 80 и
443, а на macOS порты ниже 1024 обычному пользователю недоступны. Если ты
работаешь без интерактивного терминала, выполни `sudo -v` заранее.

Не прерывай его на шаге 1/4, даже если кажется, что он завис: `npm install`
молчит несколько минут.

## Шаг 5. Проверь результат

```bash
# служба поднялась и собрала дела
curl -s http://127.0.0.1:8765/api/desktop | head -c 300; echo

# стенд доступен снаружи и закрыт паролем
curl -s -o /dev/null -w "без пароля: %{http_code}\n" "https://$CAUSA_DOMAIN/"
curl -s -o /dev/null -w "с паролем:  %{http_code}\n" -u "operator:ПАРОЛЬ" "https://$CAUSA_DOMAIN/"
```

Ожидаемое:

- первый `curl` печатает JSON с пространствами и делами;
- **без пароля — `401`**. Это не ошибка, а то, что нужно: значит HTTPS работает
  и стенд закрыт;
- **с паролем — `200`**.

Если без пароля приходит `200` — **немедленно останови Caddy**
(`sudo brew services stop caddy`) и сообщи человеку: стенд открыт всем.

## Шаг 6. Отчёт

Напиши человеку коротко и по фактам:

1. **Адрес стенда** и что он отвечает `401` без пароля и `200` с паролем.
2. **Логин и пароль** (если пароль генерировал ты).
3. Сколько дел собрал стенд — это число видно в выводе `install.sh`
   («дел собрано: N») и в JSON из шага 5.
4. Что не получилось, если что-то не получилось, — с текстом ошибки, а не
   пересказом.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `caddy не найден` | `brew install caddy` |
| сборка интерфейса падает | проверь `node --version`, нужен 20+ |
| «Стенд не ответил на 127.0.0.1:8765 за две минуты» | смотри `~/Library/Logs/verdict-causa-stand-error.log` и пришли последние 30 строк |
| скрипт дошёл до конца, но сказал «пока не отвечает» | почти всегда DNS или порт 80; повтори проверку из шага 2, Caddy продолжит попытки сам |
| `sudo` просит пароль и зависает | выполни `sudo -v` в интерактивном терминале, потом запусти скрипт заново |
| нужно поменять пароль или поддомен | `./deploy/configure.sh`, затем `sudo brew services restart caddy` |
| «Порт 80 занят процессом X, а не Caddy» | напиши человеку, что это за процесс; не выключай его сам |
| после установки перестал открываться другой сайт | верни конфигурацию из копии `Caddyfile.before-verdict-causa.*` и сообщи человеку |

Полезные команды:

```bash
launchctl stop com.verdictcausa.stand      # остановить стенд
launchctl start com.verdictcausa.stand     # запустить
sudo brew services stop caddy              # закрыть доступ снаружи
tail -50 ~/Library/Logs/verdict-causa-stand.log
tail -50 ~/Library/Logs/verdict-causa-caddy.log
```

## Чего делать не нужно

- **Не отключай `basic_auth`** в конфигурации Caddy и не «упрощай» её, чтобы
  что-то заработало. Без пароля стенд выпускать наружу нельзя.
- **Не открывай порт 8765 наружу.** Стенд слушает только `127.0.0.1`; наружу его
  выпускает Caddy, и так и должно остаться.
- **Не коммить `deploy/local/`** — там хэш пароля; каталог намеренно не
  отслеживается git.
- **Не трогай чужие сайты и сервисы.** Не останавливай процессы на портах 80 и
  443, не правь чужой `Caddyfile` руками, не запускай `brew upgrade`. Конфликт —
  это сообщение к человеку, а не задача расчистить место.
- **Не загружай в стенд документы реальных клиентов.**
- Не меняй код проекта, чтобы обойти ошибку установки. Если что-то не собирается
  — это сообщение к человеку, а не задача починить на месте.

## Обновление в будущем

```bash
cd ~/verdict-causa && git pull
./deploy/install.sh
launchctl stop com.verdictcausa.stand && launchctl start com.verdictcausa.stand
```

`configure.sh` повторять не нужно: `deploy/local/` переживает `git pull`.
Пересборка интерфейса обязательна — данные разбора вкладываются в сборку, и
старая сборка покажет старые выводы.
