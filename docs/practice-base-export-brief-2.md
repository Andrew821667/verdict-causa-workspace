# Задание агенту на Mac mini: вторая выгрузка судебной практики

Первая выгрузка принята и лежит в проекте: `data/practice/cases.jsonl`, 50 дел.
Формат в порядке, приёмная сторона читает файл без правок. Это задание — про
второй заход. Оно **самодостаточно**: первое
([`practice-base-export-brief.md`](practice-base-export-brief.md)) открывать не
нужно, всё необходимое есть здесь.

## Что показала первая выгрузка

Приёмная сторона посчитала:

| Показатель | Значение |
|---|---|
| дел всего | 50 |
| **дел с окончательным исходом** | **5** |
| дел с `outcome: иное` | 45 |
| инстанция `ВС РФ` | 50 из 50 |
| тем без единого дела | 7 из 17 |

Сверить вывод модели с судом можно только по тем 5. Остальные 45 — работа,
которая не даёт проверки.

**Причина не в невнимательности, а в отборе.** Все 50 дел — акты Верховного
Суда. Кассационное определение ВС РФ, как правило, отменяет судебные акты и
направляет дело на новое рассмотрение: правовой вывод в нём есть, а итога спора
нет. Отсюда и `иное` в 45 случаях — это следствие выбора инстанции, а не ошибка
разметки.

Поэтому главное изменение второго задания — **инстанция**, а не «постарайся
указывать исход».

---

## Что нужно сделать одной фразой

Выгрузить из базы судебной практики дела в виде плоского JSONL, где по каждому
делу указаны установленные судом обстоятельства, решение суда и ссылка на
источник, — чтобы формальная модель могла проверить себя на реальных делах.

## Два главных правила

**Не сопоставляй дела с внутренними предикатами модели и не заполняй за неё
ожидаемый результат.** Выгружай правовую суть: что суд установил и что решил.
Перевод в предикаты делает принимающая сторона. Если ты сделаешь это сам,
проверка потеряет смысл: ожидаемый итог должен приходить от суда, а не от
модели, которую проверяют.

**Не выдумывай.** Если дела по теме в базе нет — так и напиши в описи. Пустая
строка в отчёте лучше правдоподобной выдумки.

## Требование 1. Акт должен разрешать спор

Бери судебные акты, которыми спор **окончен**:

- решение первой инстанции, вступившее в силу (не обжаловано либо оставлено в
  силе);
- постановление апелляции, которым спор разрешён;
- постановление кассации, которым принят новый судебный акт (не «направить на
  новое рассмотрение»);
- определение ВС РФ **об отказе в передаче** жалобы — оно оставляет в силе
  нижестоящий акт, и итог у дела есть; в `holding_ru` тогда опиши, что именно
  оставлено в силе.

Не бери:

- определения о направлении дела на новое рассмотрение;
- определения о передаче жалобы на рассмотрение;
- акты по процессуальным вопросам (обеспечительные меры, судебные расходы,
  восстановление срока) — там нет вывода по существу спора.

Проверь себя одним вопросом: **можно ли из этого акта понять, кто и что в итоге
получил?** Если нет — дело не подходит.

**Целевой показатель: `outcome: иное` не более чем у 5 дел из 50.** Обратное
соотношение к первой выгрузке.

Дело из первой выгрузки можно взять повторно, если ты нашёл по нему
**окончательный акт**. Тогда в `notes_ru` напиши: `заменяет дело <id> из первой
выгрузки`. Поле `id` при этом сделай новым — по номеру и инстанции нового акта.

## Требование 3. Три новые темы — приоритет

Последние три строки таблицы появились только сейчас. До этого модель разбирала
эти институты, но их вывод никуда не доходил: дело по такой теме нечем было
сверять, потому что расхождение с судом просто не проявлялось в итоге. Теперь
все три доведены до итоговых выводов, и дела по ним впервые дают проверку.

**`просрочка_кредитора` (статьи 405–406).** Нужны дела, где суд отказал во
взыскании неустойки или убытков за просрочку должника, установив, что кредитор
сам не принял исполнение или не совершил действий, без которых должник не мог
исполнить. Ключевой вывод: должник не считается просрочившим.

**`прекращение_обязательства` (глава 26).** Нужны дела о зачёте, новации,
прощении долга, невозможности исполнения, совпадении должника и кредитора.
Особенно ценны дела, где суд разграничил **прекращённое обязательство** и
**требования, возникшие до прекращения** (статья 407 пункт 4): например, зачёт
провели, а неустойку за прошлую просрочку суд всё равно взыскал. Это ровно то
различие, которое модель проводит, и дело на нём проверяет её лучше всего.

**`решения_собраний` (статьи 181.1–181.5).** Нужны дела, где спорное условие
договора держалось на решении общего собрания: размер платы по договору
управления, тариф, состав услуг, порядок изменения цены. Что должно быть видно
из фабулы:

1. что какое-то **условие договора** основано на решении собрания (а не просто
   что собрание было);
2. что с решением: принято, не принято (нет большинства), ничтожно (нет кворума,
   вопрос вне повестки при неполном участии, вопрос вне компетенции), оспоримо
   (нарушен порядок созыва, равенство участников, полномочия, протокол);
3. что суд сделал с условием и с требованием по нему.

Образец — дело **45-КГ23-2-К7**: размер платы по договору управления должен
соответствовать решению общего собрания собственников, и управляющая организация
не вправе менять его в одностороннем порядке. Дела этой категории чаще всего
жилищные (споры с управляющими организациями, ТСЖ, ЖСК) и корпоративные (решения
общих собраний участников).

**По каждой из трёх тем нужно от 5 дел.** Если в базе нет — напиши в `inventory.md`
прямо, что нет, и сколько нашлось. Пустая тема лучше выдуманной.

## Формат выгрузки

Один файл `cases.jsonl`, кодировка UTF-8, **одно дело — одна строка JSON**.
Полей ровно семнадцать, ни больше ни меньше: приёмная сторона объявлена
`extra="forbid"` и отвергнет весь файл из-за одного лишнего поля.

```json
{
  "id": "a40-12345-2023",
  "court": "Арбитражный суд города Москвы",
  "instance": "первая",
  "case_number": "А40-12345/2023",
  "decision_date": "2023-05-17",
  "source_kind": "kad.arbitr.ru",
  "source_ref": "https://kad.arbitr.ru/Card/...",
  "verification": "текст_сверен_с_первоисточником",
  "articles_gk": ["199", "506"],
  "topic_tags": ["исковая_давность"],
  "fabula_ru": "Поставщик передал товар с просрочкой в 40 дней. Покупатель обратился с иском о взыскании неустойки через три года и два месяца после наступления срока поставки. Ответчик до вынесения решения заявил о применении исковой давности.",
  "holding_ru": "Суд установил истечение общего трёхлетнего срока исковой давности и наличие заявления стороны о его применении, сделанного до вынесения решения, и отказал в иске.",
  "outcome": "в_иске_отказано",
  "outcome_reason_ru": "истечение срока исковой давности по заявлению стороны",
  "quote_ru": "Истечение срока исковой давности, о применении которой заявлено стороной спора, является самостоятельным основанием к вынесению судом решения об отказе в иске.",
  "contains_personal_data": false,
  "notes_ru": ""
}
```

### Значения полей

| Поле | Что писать |
|---|---|
| `id` | краткий уникальный ключ, латиницей, из номера дела |
| `court` | название суда полностью |
| `instance` | `первая` / `апелляция` / `кассация` / `ВС РФ` |
| `case_number` | номер дела как в акте |
| `decision_date` | дата акта, `ГГГГ-ММ-ДД` |
| `source_kind` | `kad.arbitr.ru` / `обзор ВС РФ` / `постановление Пленума` / `иное` |
| `source_ref` | URL либо идентификатор записи в базе, по которому дело можно найти снова |
| `verification` | `текст_сверен_с_первоисточником` — если ты видел полный текст акта; `извлечено_из_базы_без_сверки` — если взято из индекса и полный текст не открывался |
| `articles_gk` | только те статьи, на которые суд **сослался**, строками: `"199"`, `"181.3"`, `"393.1"`. Статьи с точкой — обычные статьи ГК РФ, не ошибка |
| `topic_tags` | только значения из таблицы требования 2, буквально |
| `fabula_ru` | **обстоятельства, установленные судом**, 3–8 предложений, без оценок и без цитат из иска |
| `holding_ru` | что суд решил и на каком основании, 2–5 предложений |
| `outcome` | `иск_удовлетворён` / `в_иске_отказано` / `удовлетворён_частично` / `иное` |
| `outcome_reason_ru` | одной строкой, почему такой исход |
| `quote_ru` | дословная цитата ключевого вывода суда; если полного текста нет — пустая строка |
| `contains_personal_data` | `true`, если в тексте остались имена граждан, адреса, паспортные данные |
| `notes_ru` | свободные пометки; сюда же `заменяет дело <id> из первой выгрузки` |

### Чего в файле быть не должно

- сведений о доверителях, не являющихся стороной опубликованного судебного акта;
- имён граждан, адресов, паспортных и банковских данных — обезличь их
  (`Гражданин К.`, `ООО «П.»`), а `contains_personal_data` поставь `true`, если
  что-то осталось;
- содержимого материалов дела, не вошедшего в опубликованный акт;
- любых ключей, токенов, паролей, строк подключения.

Выгружай **только опубликованные судебные акты**. Внутренние документы по
клиентским поручениям в эту выгрузку не идут.

## Шаг 3. Самопроверка перед сдачей

Скрипт дополнен: теперь он проверяет метки тем и долю окончательных исходов —
ровно то, что подвело в первый раз.

```bash
python3 - <<'PY'
import json, collections, pathlib

TOPICS = {
    "исковая_давность", "исчисление_сроков", "злоупотребление_правом",
    "представительство", "согласие_на_сделку", "дееспособность",
    "правоспособность_юрлица", "оборотоспособность", "форма_сделки",
    "заключённость", "недействительность", "вещные_права", "расторжение",
    "нарушение_обязательства", "просрочка_кредитора",
    "прекращение_обязательства", "решения_собраний",
}
OUTCOMES = {"иск_удовлетворён", "в_иске_отказано", "удовлетворён_частично", "иное"}
NEED = {"id","court","instance","case_number","decision_date","source_kind",
        "source_ref","verification","articles_gk","topic_tags","fabula_ru",
        "holding_ru","outcome","outcome_reason_ru","quote_ru",
        "contains_personal_data","notes_ru"}

p = pathlib.Path("cases.jsonl")
ids, topics, outcomes, instances, bad = set(), collections.Counter(), collections.Counter(), collections.Counter(), 0
for n, line in enumerate(p.read_text(encoding="utf-8").splitlines(), 1):
    if not line.strip():
        continue
    try:
        row = json.loads(line)
    except Exception as exc:
        print(f"строка {n}: не JSON — {exc}"); bad += 1; continue
    extra = row.keys() - NEED
    if extra:
        print(f"строка {n}: лишние поля {sorted(extra)} — приёмная сторона их отвергнет"); bad += 1
    miss = NEED - row.keys()
    if miss:
        print(f"строка {n}: нет полей {sorted(miss)}"); bad += 1
    if row.get("id") in ids:
        print(f"строка {n}: повтор id {row.get('id')}"); bad += 1
    ids.add(row.get("id"))
    if not row.get("fabula_ru", "").strip():
        print(f"строка {n}: пустая фабула"); bad += 1
    if not row.get("holding_ru", "").strip():
        print(f"строка {n}: пустой вывод суда"); bad += 1
    if row.get("outcome") not in OUTCOMES:
        print(f"строка {n}: недопустимый outcome {row.get('outcome')!r}"); bad += 1
    for t in row.get("topic_tags", []):
        if t not in TOPICS:
            print(f"строка {n}: метка {t!r} не из списка — назови её буквально"); bad += 1
        topics[t] += 1
    outcomes[row.get("outcome")] += 1
    instances[row.get("instance")] += 1

total = len(ids)
final = total - outcomes.get("иное", 0)
print(f"\nвсего дел: {total}, ошибок: {bad}")
print(f"с окончательным исходом: {final} из {total}")
print("инстанции:", dict(instances))
print("по темам:", dict(sorted(topics.items())))
print("тем без дел:", sorted(TOPICS - set(topics)))

if total and outcomes.get("иное", 0) > max(5, total * 0.1):
    print("\nСТОП: дел без окончательного исхода слишком много — см. требование 1.")
    bad += 1
print("\nГОТОВО К СДАЧЕ" if bad == 0 else "\nНЕ СДАВАТЬ: исправь ошибки выше")
PY
```

Сдавай, только когда напечатано `ГОТОВО К СДАЧЕ`.

## Зачем это нужно — одной фразой

Первая выгрузка показала, что модель **можно** прогнать на реальных делах.
Вторая должна показать, **где она расходится с судом**. Для этого у дела должен
быть исход, с которым есть что сравнивать.
