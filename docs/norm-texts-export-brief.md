# Задание: выгрузка текстов норм и разъяснений

## Запрет, который важнее задания

**Агент не должен использовать для работы ключ API какой-либо LLM — ни свой, ни
системный, ни из окружения, ни из `.env`, ни из связки ключей. Работать только
на ресурсах подписки. Нельзя брать ключи или конфигурацию из этого проекта и из
соседних проектов на машине. Нельзя запускать ничего, что тарифицируется как
платный API. Если задачу без такого ключа выполнить нельзя — остановись и
напиши человеку.**

Задача целиком решается детерминированным разбором локальных файлов. Ни одна её
часть не требует модели: ни суммаризации, ни классификации, ни переписывания.
Текст переносится **дословно**. Если возникло желание что-то «сформулировать
короче» — это ошибка постановки, а не работы: остановись и напиши.

## Зачем это нужно

Пакет содержит 309 источников права, и текст в каждом — не норма, а пересказ в
одну-три фразы. Для статей 166–168 ГК РФ он выглядит так:

> «Синтетическое представление: ничтожность, оспоримость, надлежащий заявитель,
> законный интерес, недобросовестная ссылка и нарушение закона проверяются
> раздельно.»

Из-за этого предикаты модели **никто не может сверить с законом**: сверять не с
чем. Формальный вывод строится на предикате, предикат объявлен со ссылкой на
статью, а текста статьи в системе нет.

Данные при этом на машине есть. Прошлое задание — выгрузка структуры кодекса —
прямо запрещало их брать:

> «Не выгружай тексты статей. Нужны номера, названия и структура.»

Тогда это было верно: измерялось покрытие по номерам. Сейчас нужен текст, и
запрет снимается настоящим заданием.

## Что выгрузить

Три набора. Каждый — отдельный файл или каталог, каждый со своей описью.

### 1. Тексты статей ГК РФ, части первая и вторая

Источник — **тот же снимок**, которым бралась структура: `LAW_5142` (часть 1) и
`LAW_9027` (часть 2) в `consultant-data/kodeksy` на Mac mini. Это условие, а не
пожелание: файл обязан состыковаться с уже лежащим `data/code/gk_articles.jsonl`
по паре `(part, number)`, и `source_ref` должен остаться в том же формате
`consultant:GK1:287.5`.

Файл: `data/code/gk_article_texts.jsonl`, UTF-8, по объекту JSON на строку.

```json
{
  "part": 1,
  "number": "168",
  "text_ru": "1. За исключением случаев, предусмотренных пунктом 2 настоящей статьи...",
  "edition_date": "2026-03-25",
  "source_ref": "consultant:GK1:168"
}
```

| поле | что в нём |
|---|---|
| `part` | `1` или `2` |
| `number` | номер статьи строкой, **дословно как в структурной выгрузке** |
| `text_ru` | полный текст статьи дословно, с сохранением нумерации пунктов |
| `edition_date` | дата редакции, в которой взят текст, `YYYY-MM-DD` |
| `source_ref` | та же ссылка, что в структурной выгрузке |

**Нумерацию пунктов сохраняй.** Пункт — это следующий уровень модели: пакет
сейчас работает по статьям, а разбор по пунктам упирался ровно в отсутствие
текста. Строки вида `1.`, `2.`, `3.` в начале абзаца должны остаться на месте, а
не быть склеены в сплошной абзац.

**Утратившие силу статьи.** Если текста нет — строку всё равно включи с
`text_ru: ""`. Пропуск строки создаст дыру, неотличимую от «статью забыли».

Из локального корпуса `consultant-data/court-practice/*/converted-md/*.md` —

ссылается:

| документ | зачем |

Каталог: `data/guidance/`, по файлу на документ, имя — устойчивый слаг

Рядом — `data/guidance/index.jsonl`, по строке на документ:


Если какого-то документа в корпусе нет — **так и напиши в описи**. Не подменяй

### 3. Федеральный закон № 127-ФЗ «О несостоятельности (банкротстве)»

Нужен для нового института. Сначала **поищи** его в локальных снимках: он может
лежать рядом с кодексами или в корпусе практики. Если нашёл — выгрузи по
статьям, тем же складом, что и кодекс.

Файл: `data/laws/127fz_articles.jsonl`.

```json
{
  "number": "61.2",
  "title_ru": "Оспаривание подозрительных сделок должника",
  "chapter_number": "III.1",
  "chapter_title_ru": "Оспаривание сделок должника",
  "in_force": true,
  "text_ru": "1. Сделка, совершенная должником в течение одного года...",
  "edition_date": "2026-01-01",
  "source_ref": "consultant:127FZ:61.2"
}
```

Если закона в снимках **нет** — не ищи его в интернете и не восстанавливай по
памяти. Напиши в описи «не найден», и человек загрузит его отдельно.

## Опись

Одна на задание: `data/norm-texts-inventory.md`. В ней ответы на пять вопросов.

1. **Откуда взято.** Какие документы, какая редакция, на какую дату сохранён
   локальный снимок.
2. **Сколько получилось.** Статей с текстом и без по каждой части; документов
   разъяснений; статей закона о банкротстве.
3. **Как проверено, что текст полный.** Чем ты убедился, что статья не обрезана:
   на каком признаке кончается одна и начинается следующая, и что стало со
   статьями, где этот признак не сработал.
4. **Что не сошлось.** Номера из `gk_article_texts.jsonl`, которым не нашлось
   пары в `gk_articles.jsonl`, и наоборот. Ожидается пустой список; если он не
   пуст — это находка, а не повод подгонять.
5. **Чего в выгрузке нет.** Части третья и четвёртая; документы, которых не
   нашлось; 127-ФЗ, если его нет.

## Чего делать не нужно

- **Не переписывай текст своими словами.** Ни сокращать, ни «приводить к единому
  стилю», ни исправлять опечатки первоисточника. Дословно.
- **Не восстанавливай по памяти** ни одну норму, которой не нашёл в снимке.
  Ненайденное, названное ненайденным, полезнее выдуманной полноты.
- **Не трогай векторные индексы.** Chroma и FTS — производные; здесь нужен
  исходный MD и снимки кодексов, а не то, что построено поверх них.
- **Не выгружай части третью и четвёртую ГК.** Отдельный заход.
- **Не приноси реальные договоры.** Тоже отдельная задача, со своими правилами
  об обезличивании.

## Как сдать

Ветка `data/norm-texts-export`, основанная **на текущем `main`** (прошлая
выгрузка пришла на ветке от старого состояния, и слияние целиком удалило бы всё,
что сделано после). Коммит с файлами выгрузки и описью, push в
`verdict-causa-workspace`. Пул-реквест не открывай.

## Как проверить себя до сдачи

```bash
python - <<'PY'
import json, collections

structure = [json.loads(l) for l in open("data/code/gk_articles.jsonl", encoding="utf-8") if l.strip()]
texts = [json.loads(l) for l in open("data/code/gk_article_texts.jsonl", encoding="utf-8") if l.strip()]

s_keys = {(r["part"], r["number"]) for r in structure}
t_keys = {(r["part"], r["number"]) for r in texts}

print("статей в структуре:", len(structure), "| уникальных ключей:", len(s_keys))
print("статей с текстом:  ", len(texts), "| уникальных ключей:", len(t_keys))
print("в структуре, но без текста:", len(s_keys - t_keys))
print("текст без статьи в структуре:", sorted(t_keys - s_keys)[:10])
print("пустой text_ru:", sum(1 for r in texts if not r["text_ru"].strip()))
print("недействующих в структуре:", sum(1 for r in structure if not r["in_force"]))
lens = sorted(len(r["text_ru"]) for r in texts if r["text_ru"].strip())
if lens:
    print("длина текста: мин", lens[0], "| медиана", lens[len(lens)//2], "| макс", lens[-1])
PY
```

Сойтись должно так:

- **1298** строк в структуре и **1298** в текстах — ключи совпадают ровно;
- «текст без статьи в структуре» — **пустой список**;
- пустых `text_ru` — примерно **41**, столько же, сколько утративших силу;
- минимальная длина текста у действующей статьи — **не десятки знаков**. Если
  медиана вышла около двухсот, текст обрезан: это длина заголовка, а не статьи.

Последняя проверка важнее прочих. Ровно на ней видно, перенёс ты нормы или
только их названия.
