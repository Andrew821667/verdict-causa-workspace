Выгрузка закона о банкротстве и связанной базы

Взять 127-ФЗ и то, что КонсультантПлюс сам показывает как связанные документы, — прямо из подписки на этой машине, тем же способом, каким бралась вторая выгрузка практики.

репозиторий verdict-causa-workspace ветка data/law127fz-export основывать на main источник подписка КонсультантПлюс, Mac mini

Запрет, который важнее задания

Не использовать для работы ключ API какой-либо LLM — ни свой, ни системный, ни из окружения, ни из .env, ни из связки ключей. Работать только на ресурсах подписки. Это не про КонсультантПлюс — доступ к нему уже есть на машине, лицензирован и использовался для прошлых выгрузок. Запрет — про модели, которые тарифицируются как платный API.

Нельзя брать ключи или конфигурацию из этого проекта и из соседних проектов на машине. Если задачу без API-ключа LLM выполнить нельзя — остановись и напиши человеку. Задача целиком решается поиском и экспортом из КонсультантПлюс: текст переносится дословно, а не суммаризируется.

1

Зачем это нужно

Пакет строит институт банкротства — что несостоятельность делает с договорным требованием: режим предъявления, очерёдность, оспаривание сделок должника, сальдирование против зачёта. Материя целиком лежит в Федеральном законе от 26.10.2002 № 127-ФЗ, а не в ГК.

Прошлое задание просило поискать 127-ФЗ в уже сохранённых локальных снимках — и, если не нашёлся, честно написать «не найден». Этот заход отдельный и целевой: взять закон прямо из подписки, тем же способом, каким бралась вторая выгрузка практики.

2

Полный текст 127-ФЗ

Каталог LAW, документ «О несостоятельности (банкротстве)» от 26.10.2002 № 127-ФЗ, действующая редакция. Экспортировать постатейно, с сохранением структуры «часть → глава → параграф → статья» и нумерации пунктов внутри статьи.

Файл: data/laws/127fz_articles.jsonl, UTF-8, по объекту JSON на строку.

{
  "number": "61.2",
  "title_ru": "Оспаривание подозрительных сделок должника",
  "chapter_number": "III.1",
  "chapter_title_ru": "Оспаривание сделок должника",
  "in_force": true,
  "text_ru": "1. Сделка, совершенная должником в течение одного года...",
  "edition_date": "2026-XX-XX",
  "source_ref": "consultant:127FZ:61.2"
}

Приоритет — если постатейный экспорт целиком почему-то невозможен, эти главы обязаны войти первыми:

статьио чём
5текущие платежи
63последствия введения наблюдения для требований
61.1–61.9оспаривание сделок должника
134–138очерёдность, залоговый кредитор
142порядок расчётов с кредиторами
3

Связанные документы — только из панели связи

У карточки 127-ФЗ в системе есть панель связанных документов. Возьми из неё — не открытым поиском по всей базе — документы только двух родов: постановления Пленума / Президиума ВС РФ (и сохранившие силу постановления Пленума ВАС РФ) и обзоры судебной практики, непосредственно разъясняющие институт банкротства. Не бери комментарии, статьи, консультации специалистов и типовые формы — это не источник права для модели.

документзачем
Постановление Пленума ВАС РФ № 63 от 23.12.2010толкование главы III.1 — оспаривание сделок должника
Постановление Пленума ВАС РФ № 35 от 22.06.2012процессуальные вопросы: предъявление требований, реестр

Оба нужны точно, если система покажет их связанными. Обзор ВС РФ от 29.01.2020 о субординации уже запрошен прошлым заданием — повторно можно не брать, если он там уже лежит.

Остальные документы — по тому же критерию: прямая связь с банкротством как таковым, а не с субсидиарной ответственностью контролирующих лиц или банкротством граждан вне общего режима требований — они за пределами объёма, который строит пакет. Если сомневаешься — включи и отметь сомнение в описи; вычеркнуть лишнее проще, чем найти пропущенное.

Каталог: data/guidance/ — тот же, что в прошлом задании, не создавай параллельный. Имя файла — устойчивый слаг (plenum-vas-63-2010.md). Пополни существующий data/guidance/index.jsonl, а не переписывай его.

4

Опись

data/law127fz-inventory.md. Ответы на четыре вопроса.

  1. Редакция и дата. На какую дату сохранён снимок 127-ФЗ, каким актом заканчивается перечень изменяющих документов.
  2. Сколько статей выгружено, сколько с пустым текстом и почему.
  3. Что взято из связанных документов — список с источником (панель связи, а не отдельный поиск) — и что сознательно не взято, с причиной.
  4. Чего не нашлось. Если сам 127-ФЗ или названные постановления не обнаружены — прямо так и написать, не подменяя и не восстанавливая по памяти.
5

Как сдать и как проверить себя

Ветка data/law127fz-export, основанная на текущем main. Коммит с файлами выгрузки и описью, push в verdict-causa-workspace. Пул-реквест не открывай.

Если ветка data/norm-texts-export из прошлого задания уже существует и не слита — не трогай её и не наследуй от неё: основывайся на main, чтобы два захода не зависели друг от друга по порядку выполнения. 

python - <<'PY'
import json

articles = [json.loads(l) for l in open("data/laws/127fz_articles.jsonl", encoding="utf-8") if l.strip()]
print("статей 127-ФЗ:", len(articles))
print("пустой text_ru:", sum(1 for r in articles if not r["text_ru"].strip()))
required = {"5", "63", "61.1", "61.2", "61.3", "61.9", "134", "135", "138", "142"}
present = {r["number"] for r in articles}
print("обязательных статей не хватает:", sorted(required - present))
lens = sorted(len(r["text_ru"]) for r in articles if r["text_ru"].strip())
if lens:
    print("длина текста: мин", lens[0], "| медиана", lens[len(lens)//2], "| макс", lens[-1])

guidance = [json.loads(l) for l in open("data/guidance/index.jsonl", encoding="utf-8") if l.strip()]
print("документов в index.jsonl:", len(guidance))
PY

«Обязательных статей не хватает» должно выйти пустым списком; если что-то пропущено — либо статья утратила силу (тогда так и отметь в описи), либо экспорт задел не всё, что требовалось.
