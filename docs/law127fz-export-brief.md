# Задание: выгрузка закона о банкротстве и связанной с ним базы

## Запрет, который важнее задания

**Агент не должен использовать для работы ключ API какой-либо LLM — ни свой, ни
системный, ни из окружения, ни из `.env`, ни из связки ключей. Работать только
на ресурсах подписки.** Это не про КонсультантПлюс — доступ к нему уже есть на
машине, лицензирован и использовался для прошлых выгрузок. Запрет — про
модели, которые тарифицируются как платный API.

Нельзя брать ключи или конфигурацию из этого проекта и из соседних проектов на
машине. Если задачу без API-ключа LLM выполнить нельзя — остановись и напиши
человеку. Задача целиком решается поиском и экспортом из КонсультантПлюс:
текст переносится дословно, а не суммаризируется.

## Зачем это нужно

Пакет строит институт банкротства — что несостоятельность делает с договорным
требованием: режим предъявления, очерёдность, оспаривание сделок должника,
сальдирование против зачёта. Материя целиком лежит в Федеральном законе от
26.10.2002 № 127-ФЗ «О несостоятельности (банкротстве)», а не в ГК.

Прошлое задание (`docs/norm-texts-export-brief.md`) просило поискать 127-ФЗ в
уже сохранённых локальных снимках — и, если не нашёлся, честно написать «не
найден». Этот заход отдельный и целевой: взять закон и связанную с ним базу
прямо из подписки КонсультантПлюс на этой машине, тем же способом, каким
бралась вторая выгрузка практики.

## Что выгрузить

### 1. Полный текст 127-ФЗ

Каталог `LAW`, документ «О несостоятельности (банкротстве)» от 26.10.2002 №
127-ФЗ, действующая редакция. Экспортировать **постатейно**, в MD, с
сохранением структуры «часть → глава → параграф → статья» и нумерации пунктов
внутри статьи.

Файл: `data/laws/127fz_articles.jsonl`, UTF-8, по объекту JSON на строку.

```json
{
  "number": "61.2",
  "title_ru": "Оспаривание подозрительных сделок должника",
  "chapter_number": "III.1",
  "chapter_title_ru": "Оспаривание сделок должника",
  "in_force": true,
  "text_ru": "1. Сделка, совершенная должником в течение одного года...",
  "edition_date": "2026-XX-XX",
  "source_ref": "consultant:127FZ:61.2"
}
```

Приоритет — если экспорт постатейно почему-то невозможен, эти главы обязаны
войти в первую очередь: **статья 5** (текущие платежи), **статья 63** (последствия
введения наблюдения для требований), **глава III.1, статьи 61.1–61.9**
(оспаривание сделок должника), **статьи 134–138** (очерёдность, залоговый
кредитор), **статья 142** (порядок расчётов с кредиторами).

### 2. Документы, которые КонсультантПлюс сам показывает как связанные

У карточки 127-ФЗ в системе есть панель связанных документов. Возьми из неё —
не открытым поиском по всей базе, а именно оттуда — документы **только двух
родов**: постановления Пленума / Президиума ВС РФ (и сохранившие силу
постановления Пленума ВАС РФ) и обзоры судебной практики, непосредственно
разъясняющие институт банкротства. Не бери комментарии, статьи, консультации
специалистов и типовые формы — это не источник права для модели.

Два документа нужны точно, если система их покажет как связанные:

| документ | зачем |
|---|---|
| Постановление Пленума ВАС РФ от 23.12.2010 № 63 | толкование главы III.1 — оспаривание сделок должника |
| Постановление Пленума ВАС РФ от 22.06.2012 № 35 | процессуальные вопросы: предъявление требований, реестр |

Обзор ВС РФ от 29.01.2020 о субординации уже запрошен прошлым заданием —
повторно можно не брать, если он там уже лежит.

Остальные документы бери по тому же критерию — прямая связь с институтом
банкротства как таковым, а не с отдельными его сторонами вроде субсидиарной
ответственности контролирующих лиц (глава III.2) или банкротства граждан вне
общего режима требований: они за пределами объёма, который строит пакет.
Если сомневаешься, включать документ или нет, — включи и отметь сомнение в
описи; вычеркнуть лишнее проще, чем найти пропущенное.

Каталог: `data/guidance/`, тот же, что в прошлом задании — не создавай
параллельный. Имя файла — устойчивый слаг (`plenum-vas-63-2010.md`), формат тот
же, что уже используется. Пополни существующий `data/guidance/index.jsonl`, а
не переписывай его.

## Опись

`data/law127fz-inventory.md`. Ответы на четыре вопроса:

1. **Редакция и дата.** На какую дату сохранён локальный снимок 127-ФЗ, каким
   актом заканчивается перечень изменяющих документов.
2. **Сколько статей выгружено**, сколько с пустым текстом и почему.
3. **Что взято из связанных документов** — список с источником (панель связи, а
   не отдельный поиск) — и что сознательно не взято из этой панели с причиной.
4. **Чего не нашлось.** Если сам 127-ФЗ или названные постановления Пленума
   не обнаружены в подписке — прямо так и написать, не подменяя и не
   восстанавливая по памяти.

## Как сдать

Ветка `data/law127fz-export`, основанная на текущем `main`. Коммит с файлами
выгрузки и описью, push в `verdict-causa-workspace`. Пул-реквест не открывай.

Если ветка `data/norm-texts-export` из прошлого задания уже существует и не
слита — не трогай её и не наследуй от неё: основывайся на `main`, как указано
выше, чтобы два захода не зависели друг от друга по порядку выполнения.

## Как проверить себя до сдачи

```bash
python - <<'PY'
import json

articles = [json.loads(l) for l in open("data/laws/127fz_articles.jsonl", encoding="utf-8") if l.strip()]
print("статей 127-ФЗ:", len(articles))
print("пустой text_ru:", sum(1 for r in articles if not r["text_ru"].strip()))
required = {"5", "63", "61.1", "61.2", "61.3", "61.9", "134", "135", "138", "142"}
present = {r["number"] for r in articles}
print("обязательных статей не хватает:", sorted(required - present))
lens = sorted(len(r["text_ru"]) for r in articles if r["text_ru"].strip())
if lens:
    print("длина текста: мин", lens[0], "| медиана", lens[len(lens)//2], "| макс", lens[-1])

guidance = [json.loads(l) for l in open("data/guidance/index.jsonl", encoding="utf-8") if l.strip()]
print("документов в index.jsonl:", len(guidance))
PY
```

«Обязательных статей не хватает» должно выйти пустым списком; если что-то
пропущено — это либо статья утратила силу (тогда так и отметь в описи), либо
экспорт задел не всё, что требовалось.
