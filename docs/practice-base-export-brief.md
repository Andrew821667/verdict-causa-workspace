# Задание агенту на Mac mini: выгрузка судебной практики

Документ передаётся агенту, работающему на Mac mini, где лежит база судебной
практики. Результат выгрузки принимает набор `practice_scenarios` в проекте
`verdict-causa-workspace`.

## Задача одной фразой

Выгрузить из базы судебной практики дела в виде плоского JSONL, где по каждому
делу указаны установленные судом обстоятельства, решение суда и ссылка на
источник, — чтобы формальная модель могла проверить себя на реальных делах.

## Главное правило

**Не сопоставляй дела с внутренними предикатами модели и не заполняй за неё
ожидаемый результат.** Выгружай правовую суть: что суд установил и что решил.
Перевод в предикаты делает принимающая сторона. Если ты сделаешь это сам,
проверка потеряет смысл: ожидаемый итог должен приходить от суда, а не от
модели, которую проверяют.

**Не выдумывай.** Если дела по теме в базе нет — так и напиши в описи. Пустая
строка в отчёте лучше правдоподобной выдумки.

Ищи признаки корпуса практики: таблицы с решениями, эмбеддингами, номерами дел

**Отчитайся описью до выгрузки** — файл `inventory.md`:

## Шаг 1. Отобрать дела по темам

Нужны дела, где суд **высказался по существу** по одной из тем ниже. Цель —
**от 5 до 10 дел на тему, минимум 50 всего**. Если по теме меньше — выгрузи
сколько есть и отметь нехватку.

Значения `topic_tags` бери **дословно из левого столбца**: принимающая сторона
сверяет метки с этим перечнем, и метка, названная своими словами, в него не
попадает.

| Значение `topic_tags` | Тема | Статьи ГК РФ |
|---|---|---|
| `исковая_давность` | исковая давность, заявление о её применении | 195–208, особенно 199 |
| `исчисление_сроков` | исчисление сроков | 190–194 |
| `злоупотребление_правом` | злоупотребление правом, отказ в защите | 10 |
| `представительство` | сделка неуполномоченного лица, одобрение | 183 |
| `согласие_на_сделку` | согласие на совершение сделки | 157.1, 173.1 |
| `дееспособность` | дееспособность гражданина | 29, 30, 171, 172, 176 |
| `правоспособность_юрлица` | правоспособность юридического лица | 49, 173 |
| `оборотоспособность` | оборотоспособность объекта, ничтожность | 129, 168 |
| `форма_сделки` | форма сделки и её порок | 158–165, особенно 162 |
| `заключённость` | заключённость договора | 432, 433, 438 |
| `недействительность` | недействительность и реституция | 166–181, 167 |
| `вещные_права` | продажа чужой вещи, виндикация | 209, 301, 302 |
| `расторжение` | изменение и расторжение договора | 450–453 |
| `нарушение_обязательства` | нарушение обязательства | 309–328, 393 |

Приоритет: **поставка и купля-продажа между юридическими лицами** — это профиль
демонстрационного дела в принимающем проекте.

Предпочитай дела, где **иск отклонён** или **удовлетворён частично**: они
информативнее для проверки, чем дела, где всё удовлетворено.

**Нужен окончательный исход спора.** Определение высшей инстанции, которое
отменяет акты и направляет дело на новое рассмотрение, содержит правовой вывод,
но не содержит итога: сверить с ним вывод модели по делу нельзя, и такое дело
помечается `иное`. Поэтому предпочитай акты, которыми спор разрешён по
существу, — решения первой инстанции, оставленные в силе, апелляционные
постановления, отказные определения. В первой выгрузке окончательный исход был
только у 5 дел из 50; это главное, что стоит исправить.

## Шаг 2. Формат выгрузки

Один файл `cases.jsonl`, кодировка UTF-8, **одно дело — одна строка JSON**.

```json
{
  "id": "a40-12345-2023",
  "court": "Арбитражный суд города Москвы",
  "instance": "первая",
  "case_number": "А40-12345/2023",
  "decision_date": "2023-05-17",
  "source_kind": "kad.arbitr.ru",
  "source_ref": "https://kad.arbitr.ru/Card/...",
  "verification": "текст_сверен_с_первоисточником",
  "articles_gk": ["199", "506"],
  "topic_tags": ["исковая_давность", "поставка"],
  "fabula_ru": "Поставщик передал товар с просрочкой в 40 дней. Покупатель обратился с иском о взыскании неустойки через три года и два месяца после наступления срока поставки. Ответчик до вынесения решения заявил о применении исковой давности.",
  "holding_ru": "Суд установил истечение общего трёхлетнего срока исковой давности и наличие заявления стороны о его применении, сделанного до вынесения решения, и отказал в иске.",
  "outcome": "в_иске_отказано",
  "outcome_reason_ru": "истечение срока исковой давности по заявлению стороны",
  "quote_ru": "Истечение срока исковой давности, о применении которой заявлено стороной спора, является самостоятельным основанием к вынесению судом решения об отказе в иске.",
  "contains_personal_data": false,
  "notes_ru": ""
}
```

### Значения полей

| Поле | Что писать |
|---|---|
| `id` | краткий уникальный ключ, латиницей, из номера дела |
| `instance` | `первая` / `апелляция` / `кассация` / `ВС РФ` |
| `source_kind` | `kad.arbitr.ru` / `обзор ВС РФ` / `постановление Пленума` / `иное` |
| `source_ref` | URL либо идентификатор записи в базе, по которому дело можно найти снова |
| `verification` | `текст_сверен_с_первоисточником` — если ты видел полный текст акта; `извлечено_из_базы_без_сверки` — если взято из индекса и полный текст не открывался |
| `articles_gk` | только те статьи, на которые суд **сослался**, строками: `"199"`, `"181.3"`, `"393.1"`. Статьи с точкой — обычные статьи ГК РФ, не ошибка |
| `fabula_ru` | **обстоятельства, установленные судом**, 3–8 предложений, без оценок и без цитат из иска |
| `holding_ru` | что суд решил и на каком основании, 2–5 предложений |
| `outcome` | `иск_удовлетворён` / `в_иске_отказано` / `удовлетворён_частично` / `иное` |
| `quote_ru` | дословная цитата ключевого вывода суда; если полного текста нет — пустая строка |
| `contains_personal_data` | `true`, если в тексте остались имена граждан, адреса, паспортные данные |

### Чего в файле быть не должно

- сведений о доверителях, не являющихся стороной опубликованного судебного акта;
- имён граждан, адресов, паспортных и банковских данных — обезличь их
  (`Гражданин К.`, `ООО «П.»`), а `contains_personal_data` поставь `true`, если
  что-то осталось;
- содержимого материалов дела, не вошедшего в опубликованный акт;
- любых ключей, токенов, паролей, строк подключения.

Выгружай **только опубликованные судебные акты**. Внутренние документы по
клиентским поручениям в эту выгрузку не идут.

## Шаг 3. Самопроверка перед сдачей

```bash
python3 - <<'PY'
import json, collections, pathlib
p = pathlib.Path("cases.jsonl")
need = {"id","court","instance","case_number","decision_date","source_kind",
        "source_ref","verification","articles_gk","topic_tags","fabula_ru",
        "holding_ru","outcome","outcome_reason_ru","quote_ru",
        "contains_personal_data","notes_ru"}
ids, topics, bad = set(), collections.Counter(), 0
for n, line in enumerate(p.read_text(encoding="utf-8").splitlines(), 1):
    if not line.strip():
        continue
    try:
        row = json.loads(line)
    except Exception as exc:
        print(f"строка {n}: не JSON — {exc}"); bad += 1; continue
    miss = need - row.keys()
    if miss:
        print(f"строка {n}: нет полей {sorted(miss)}"); bad += 1
    if row.get("id") in ids:
        print(f"строка {n}: повтор id {row.get('id')}"); bad += 1
    ids.add(row.get("id"))
    if not row.get("fabula_ru", "").strip():
        print(f"строка {n}: пустая фабула"); bad += 1
    if row.get("outcome") not in {"иск_удовлетворён","в_иске_отказано",
                                  "удовлетворён_частично","иное"}:
        print(f"строка {n}: недопустимый outcome {row.get('outcome')!r}"); bad += 1
    for t in row.get("topic_tags", []):
        topics[t] += 1
print(f"\nвсего дел: {len(ids)}, ошибок: {bad}")
print("по темам:", dict(topics))
PY
```

Сдавай, только когда `ошибок: 0`.

## Шаг 4. Как передать

Положи рядом два файла:

```
inventory.md    — опись базы из шага 0
cases.jsonl     — выгрузка
```

Дальше любой из способов:

1. **Ветка в репозитории** — предпочтительно:
   ```bash
   cd /path/to/verdict-causa-workspace
   git checkout -b data/practice-base-export
   mkdir -p data/practice
   cp cases.jsonl inventory.md data/practice/
   git add data/practice && git commit -m "Add court practice export from the Mac mini base"
   git push -u origin data/practice-base-export
   ```
2. Загрузить оба файла в Google Drive той же учётной записи.
3. Приложить файлы в чат.

## Что произойдёт дальше — чтобы ты понимал смысл работы

Принимающая сторона:

1. прочитает `cases.jsonl`;
2. по каждому делу переведёт установленные судом обстоятельства во внутренние
   предикаты институтов (недействительность, давность, форма, представительство,
   лица, объекты и прочие);
3. возьмёт `outcome` и `holding_ru` как **ожидаемый результат**;
4. прогонит дело через формальный анализ целиком;
5. сверит вывод системы с решением суда и отчитается, где они разошлись.

Поэтому качество `fabula_ru` и `holding_ru` определяет всю ценность выгрузки.
Фабула должна позволять ответить на вопросы: договор заключён? форма соблюдена?
есть основания недействительности? заявлена ли давность? кто подписал? что
является предметом?

Если в деле чего-то из этого не видно — не додумывай, просто не пиши. Отсутствие
факта тоже информация.
