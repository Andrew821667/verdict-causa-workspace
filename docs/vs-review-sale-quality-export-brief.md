# Задание: выгрузка обзора практики ВС РФ о недостатках товара

## Запрет, который важнее задания

**Агент не должен использовать проект для работы и в особенности ключ АПИ
любой ЛЛМ!!! Он должен работать используя ресурсы подписки!**

Задача решается экспортом из локальной подписки КонсультантПлюс тем же
способом, каким выгружены 127-ФЗ и постановления Пленума, — детерминированно,
без модели. Если без ключа API LLM задачу выполнить нельзя — остановись и
напиши человеку.

## Зачем это нужно

В пакете остался ровно один источник, который несёт наш пересказ вместо
текста первоисточника, — `synthetic-ru-vs-review2024-sale-quality-v1`.
Все остальные 215 дословных источников пересажены на настоящий текст:
190 статей ГК, 11 статей 127-ФЗ, 14 постановлений Пленума.

Пересказ звучит так:

> Гарантийный срок влияет на распределение бремени доказывания, а
> безрезультатный гарантийный ремонт не прекращает предусмотренные законом
> требования покупателя.

Разбор показал, что эта одна фраза склеивает две разные вещи, и только вторая
требует выгрузки:

1. **«гарантийный срок влияет на распределение бремени доказывания»** — это
   не позиция суда, а дословный пункт 2 статьи 476 ГК РФ, и он уже лежит
   настоящим текстом в источнике `synthetic-ru-gk465-477-sale-conformity-v1`.
   Обзор эту норму не создаёт, а применяет. **Выгружать нечего.**
2. **«безрезультатный гарантийный ремонт не прекращает предусмотренные
   законом требования покупателя»** — вот это действительно позиция ВС РФ.
   Ближайшая норма, абзац пункта 2 статьи 475 ГК о недостатках,
   «проявляющихся вновь после их устранения», говорит о существенности
   нарушения, а не о судьбе требований после неудачного ремонта. **Вот её
   первоисточник и нужен.**

## Что мешает выгрузить это без разбора

Ссылка в источнике названа так:

> Обзор судебной практики ВС РФ № 2, 3 (2024), определение № 301-ЭС23-10631

Это **три разных документа в одной строке**: обзор № 2 (2024), обзор № 3
(2024) и определение по конкретному делу. Какой пункт какого обзора имеется в
виду, из ссылки не следует. Ровно та же неоднозначность встречалась при
пересадке постановлений Пленума: там её пришлось снимать явной таблицей
соответствий, а не догадкой по тексту ссылки.

Поэтому **первая часть задания — не выгрузка, а установление факта**: в каком
из двух обзоров и в каком его пункте изложена позиция о безрезультатном
гарантийном ремонте, и совпадает ли этот пункт с определением
№ 301-ЭС23-10631.

## Что выгрузить

### Часть 1: найти пункт

Найди в КонсультантПлюс оба документа:

- Обзор судебной практики Верховного Суда Российской Федерации № 2 (2024)
- Обзор судебной практики Верховного Суда Российской Федерации № 3 (2024)

В разделе по экономическим спорам (Судебная коллегия по экономическим спорам)
найди пункт, излагающий позицию: безрезультатный (неудачный) гарантийный
ремонт не лишает покупателя требований, предусмотренных законом. Проверь,
основан ли этот пункт на определении № 301-ЭС23-10631.

**Если пункта нет ни в одном из двух обзоров** — не подгоняй, а напиши об
этом прямо в отчёте и приложи оглавления обоих обзоров по разделу
экономических споров. Отрицательный результат здесь тоже результат: он будет
означать, что ссылка в источнике неверна и её надо исправлять, а не выгрузку
делать.

### Часть 2: выгрузить текст

Файл: `data/guidance/vs_review_paragraphs.jsonl`, UTF-8, по объекту JSON на
строку — одна строка на пункт обзора:

```json
{
  "document_slug": "vs-review-3-2024",
  "document_title_ru": "Обзор судебной практики Верховного Суда Российской Федерации № 3 (2024)",
  "approved_date": "2024-11-27",
  "paragraph": "12",
  "section_ru": "Практика применения законодательства об обязательствах",
  "text_ru": "текст пункта дословно",
  "case_ref": "Определение № 301-ЭС23-10631",
  "source_ref": "consultant:LAW:XXXXXX:12"
}
```

| поле | что в нём |
|---|---|
| `document_slug` | `vs-review-2-2024` либо `vs-review-3-2024` |
| `document_title_ru` | полное название обзора, как в карточке документа |
| `approved_date` | дата утверждения Президиумом ВС РФ, `ГГГГ-ММ-ДД` |
| `paragraph` | номер пункта строкой, как в документе |
| `section_ru` | название раздела обзора, в котором стоит пункт |
| `text_ru` | текст пункта дословно, без разметки страницы |
| `case_ref` | номер определения, если пункт его называет; иначе `""` |
| `source_ref` | ссылка на карточку в КонсультантПлюс |

Выгрузи **весь раздел** обзора, в котором нашёлся нужный пункт, а не один
пункт: соседние пункты того же раздела почти наверняка понадобятся, а
повторная выгрузка стоит дороже, чем лишние двадцать строк сейчас.

## Чего в тексте быть не должно

Это главное требование, и оно выведено из трёх уже случившихся порч
выгрузок — не из осторожности вообще.

Не дамп HTML-страницы, а постатейная выгрузка из карточки документа. В
`text_ru` не должно быть:

- всплывающих подсказок похожих дел (`<div>`, карточки дел) — на этом
  однажды потерялись 65 пунктов постановления Пленума № 25/2015 при попытке
  вычистить разметку кодом;
- обрывков постраничной навигации («Статья N. Название  Статья M. Название»,
  склеенные двойным пробелом) — этим оказались испорчены 518 из 565 статей
  первой выгрузки 127-ФЗ;
- редакционного аппарата КонсультантПлюс: блоков «Путеводитель по судебной
  практике ... по ст. N» со списком вопросов пунктами `- ...` и подписей
  гиперссылок «(см. текст в предыдущей редакции)» — этим оказался засорён
  141 источник из 215, и нашлось это только на третий заход.

Пометки вида «(п. 1 в ред. Федерального закона от 17.12.1999 N 213-ФЗ)» —
законодательные, часть официального текста; их **оставляй**.

## Как проверить себя до отправки

1. Число строк в файле равно числу пунктов выгруженного раздела — сверь по
   оглавлению документа, а не по ощущению.
2. Номера пунктов идут подряд, без пропусков. Пропуск номера — признак того,
   что пункт исчез при очистке разметки; именно так была поймана потеря 65
   пунктов у Пленума.
3. Ни в одном `text_ru` нет подстрок `Путеводитель`, `(см. текст в
   предыдущей редакции)`, `<div`, `<a href`, а также абзацев, начинающихся
   с `- `.
4. Ни один `text_ru` не пуст и не короче 200 символов.

Отчёт напиши по-русски: сколько пунктов выгружено, из какого обзора, какой
пункт содержит искомую позицию, подтвердилась ли связь с определением
№ 301-ЭС23-10631, и какие из четырёх самопроверок ты прогнал.

## Ветка и коммит

Ветка `data/vs-review-sale-quality-export`. В коммите — ровно два файла:
`data/guidance/vs_review_paragraphs.jsonl` и запись о документе в
`data/guidance/index.jsonl`. Ничего в `src/` не трогай: пересадка источника
на этот текст — отдельная работа на стороне проекта.
